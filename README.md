# routine

Монорепозиторій на **pnpm workspaces + Turborepo**.

| Пакет          | Стек                                            | Порт   |
| -------------- | ----------------------------------------------- | ------ |
| `@routine/api` | NestJS 12 (ESM, Vitest)                         | `4000` |
| `@routine/web` | Next.js 16 (App Router, Tailwind v4, next-intl) | `3000` |

## Структура

```
.
├── apps/
│   ├── api/              # NestJS API, глобальний префікс /api
│   └── web/              # Next.js застосунок
├── packages/
│   └── contracts/        # zod-схеми, типи й коди помилок, спільні для api та web
├── eslint.config.mjs     # єдиний flat-config ESLint на весь репозиторій
├── tsconfig.base.json    # спільні compilerOptions, які розширюють застосунки
├── turbo.json            # граф задач і кешування
├── docker-compose.yml    # локальний Postgres
└── .husky/               # pre-commit (lint-staged) + commit-msg (commitlint)
```

## Старт

```bash
corepack enable pnpm                        # один раз
pnpm install
docker compose up -d                        # Postgres на localhost:5433
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env
pnpm --filter @routine/api db:deploy        # застосувати міграції
pnpm --filter @routine/api db:seed          # створити адміна з ADMIN_* у apps/api/.env
pnpm dev                                    # web :3000, api :4000
```

Відкрий http://localhost:3000 і увійди під адміном. Решта людей потрапляють у застосунок лише через
**Запрошення**: посилання показується один раз після створення, його треба скопіювати й надіслати.

## Доступ

- Дані належать **простору**. Реєстраційний інвайт створює власний простір; запрошена в простір людина
  живе в ньому, без окремого порожнього.
- Запрошення у простір видає його власник — людина бачить і редагує всі дані цього простору.
- Запрошення «окремий акаунт» (без простору) видає лише адмін.
- Сесія — httpOnly-cookie, у БД зберігається лише sha256 токена. Браузер ходить на `/api` того ж
  домену, а Next проксує запити в Nest, тож CORS і SameSite=None не потрібні.

## Модулі

| Модуль  | API                             | Web                              | Схема БД   |
| ------- | ------------------------------- | -------------------------------- | ---------- |
| Вішліст | `apps/api/src/modules/wishlist` | `apps/web/src/features/wishlist` | `wishlist` |
| Фінанси | `apps/api/src/modules/finance`  | `apps/web/src/features/finance`  | `finance`  |

Новий модуль = папка в `modules/` на беку, у `features/` на фронті та власна схема Postgres.
Між модулями — лише експортовані сервіси; спільні лише користувачі, простори й auth.

**Вішліст** — одна канбан-дошка на простір: **Бажання · Потреби · Роздуми · Виконано** (куплено /
подаровано). Замість списків — категорії бажань. У кожного бажання є «для кого»: учасник простору або
«спільне». Людина, для якої бажання, **ніколи не бачить його резервацій** (API віддає `reservation: null`).
Особисте посилання `/w/<token>` показує друзям лише «Бажання» й «Потреби» цієї людини; гість резервує з
імʼям і httpOnly-cookie. Порядок карток — дробові позиції з перенумерацією колонки, коли вичерпується
точність. Ціни — цілі копійки + валюта.

**Фінанси** — ручний облік без банківських API:

- **Операції:** витрати за категоріями й доходи — фіксовані або позапланові, з тим, хто витратив.
- **Регулярні доходи** («зарплата 5-го») створюють операції самі — **ліниво при читанні**, без крону (Render free
  засинає). `generatedThrough` рухається лише вперед, тож видалена вручну операція не відроджується, а пауза
  не доганяє пропущені місяці.
- **Готівка** — одна скарбничка на простір у будь-яких валютах; взяти більше, ніж лежить, не можна.
- **Депозити** — щоденне нарахування, щомісячна капіталізація або виплата, податок (за замовчуванням 23%),
  строк і опція «віднімати поповнення з доходів» (за замовчуванням увімкнена: внески зменшують залишок
  місяця й показуються на графіку доходів і витрат). Планові поповнення створюються за графіком; прогноз: до сьогодні — факт, далі — план
  (`deposit-math.ts`, покрито юніт-тестами).
- **Аналітика** — щомісячні підсумки в гривні. Суми в USD/EUR перераховуються за курсом НБУ на дату операції
  (кеш у `finance.ExchangeRate`; у тестах `RATES_SOURCE=fixed`, без мережі). Гроші — копійки, ставки — базисні
  пункти, дати — `YYYY-MM-DD` у поясі `APP_TIMEZONE`.

**Профіль** (`/profile`, для всіх, зокрема запрошених): імʼя, фото й пароль. Фото стискається в браузері до 256px
JPEG і зберігається в Postgres (`UserAvatar`); тип перевіряється за сигнатурою байтів, віддається з
`nosniff` і версійованим URL. Після зміни пароля інші пристрої виходять. Пошта привʼязана до запрошення й не
змінюється.

## Дизайн

Графіки — власні HTML/SVG-компоненти (`src/components/charts`) із табличним переглядом; кольори серій
(`--series-1/2`) перевірено валідатором на дальтонізм і контраст в обох темах.

Семантичні токени в `apps/web/src/app/globals.css` (`bg-card`, `text-muted-foreground`, `bg-primary`…) з
окремими значеннями для світлої й темної теми. Компоненти не знають конкретних кольорів — нові модулі
автоматично виглядають однаково. Базові компоненти — `src/components/ui`, без сторонньої UI-бібліотеки.

## Мови й тема

- Інтерфейс: українська, російська, англійська (`apps/web/messages`). Мова — з cookie, при першому
  візиті — з `Accept-Language`.
- API і zod-схеми повертають **коди** (`AUTH_INVALID_CREDENTIALS`, `validation.emailInvalid`), тексти живуть
  лише в перекладах. `src/i18n/messages-check.ts` валить typecheck, якщо в якійсь мові бракує ключа.
- У клієнтських компонентах не форматуйте через `Intl`: Node і браузер мають різні дані ICU, і
  гідратація падає. Дати форматує сервер, ціни — детермінований `formatPrice`.

## Команди

| Команда          | Що робить                                  |
| ---------------- | ------------------------------------------ |
| `pnpm dev`       | dev-режим для всіх застосунків             |
| `pnpm dev:api`   | лише NestJS у watch-режимі                 |
| `pnpm dev:web`   | лише Next.js                               |
| `pnpm build`     | продакшн-збірка всього                     |
| `pnpm lint`      | ESLint по всьому репозиторію               |

| `pnpm typecheck` | `tsc --noEmit` у кожному застосунку        |

| `pnpm test:e2e`  | e2e-тести API                              |
| `pnpm clean`     | чистить артефакти збірки та `node_modules` |

Додати задачу лише для одного пакета: `pnpm turbo run <task> --filter=@routine/api`.

## Домовленості

- **TypeScript 6** з єдиною базою в `tsconfig.base.json` (`strict`, `noUncheckedIndexedAccess`).
- **ESLint** — flat-config з типізованими правилами (`recommendedTypeChecked`), сортуванням імпортів
  і окремими блоками для Nest та Next. Prettier вимикає конфліктні правила останнім у ланцюжку.
- **Коміти** — Conventional Commits (`feat(api): ...`), перевіряє commitlint у `commit-msg`.
- **pre-commit** — lint-staged проганяє ESLint `--fix` та Prettier лише по застейджених файлах.
- Конфігурація Nest-застосунку винесена в `apps/api/src/app.setup.ts`, щоб e2e-тести
  запускали рівно ту саму поведінку, що й `main.ts`.
